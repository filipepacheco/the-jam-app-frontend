## Design Context

### Users

Jam App serves three primary contexts: musicians joining and managing participation from phones in active, noisy venues; hosts making fast, precise decisions while running a live Jam; and audiences following the Public Dashboard from shared screens at a distance. Developers and maintainers also need a private, reliable component system that keeps those product experiences coherent without slowing feature delivery.

### Brand Personality

Energetic, social, and music-native. The product should feel welcoming and lively without becoming noisy, and operationally precise when hosts are controlling a live Jam. It should create confidence, visible participation, and anticipation rather than feeling like generic administrative software.

### Aesthetic Direction

Use a distinctive purple/violet brand anchor with purposeful semantic color, expressive but disciplined typography, and clear visual rhythm. The interface is mobile-first and venue-ready, supports both light and dark user-selectable DaisyUI themes, and treats Portuguese as the reference language while remaining robust in English and Spanish. Avoid generic dashboard card grids, decorative gradients or glow-heavy dark UI, excessive glass effects, and visual redesign that obscures established behavior.

### Design Principles

1. Put music and active participation at the center; supporting controls should not compete with the current Jam.
2. Adapt by context: one-handed phone use for musicians, speed and precision for hosts, and distance legibility for shared displays.
3. Reveal complexity progressively, with unmistakable feedback for live and destructive operations.
4. Use semantic foundations and canonical component families while preserving meaningful domain differences.
5. Design and test every important state across themes, localization, keyboard use, reduced motion, long content, and responsive layouts.
